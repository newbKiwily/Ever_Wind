서버 계층 구성 변경 — 2026-11-12

적용 범위
- C++ 게임 서버의 계층 구성, 콜백 연결, 수신 큐, 요청 파싱 및 응답 경로 정리.
- Unity 씬·클라이언트 코드·패킷 바이트 형식·게임 규칙은 변경하지 않음.
- 성능 최적화 또는 새로운 스레드 추가 없이 시스템 구조를 구체화함.

코드에서 볼 위치
1. Gameplay/ServerSteps.h
   receive: ReceiveStep — IOCP 작업 스레드에서 전달된 소유 바이트와 연결 정보를 큐에 저장.
   validation: GameplayValidation — 원시 패킷 검사·파싱 및 공통/기능별 체인 검사.
   processing: GameplayProcessor — 승인 실행, 거절 보정, 재전송 ACK, 서버 상태 변경 및 결과 생성.
   send: SendStep — 결과를 등록된 전송 어댑터로 전달하고, 잘못된 프레임은 연결 종료 어댑터로 전달.

2. Gameplay/ServerRuntime.cpp의 ConnectSteps()
   receive -> validation.OnReceived
   validation -> processing.OnValidated
   validation의 원시 패킷 오류 -> send.OnInvalidPacket
   processing -> send.OnOutput
   이 연결은 생성 시 한 번만 조립하며, 실행 중에는 콜백을 호출한다.

3. main.cpp
   서버 외부 구성 지점이다. DB 저장소와 Service를 생성하고 IOCP의 게임 패킷 입력 콜백을 등록한다.
   세션은 weak_ptr로 캡처하며, 수신 버퍼는 큐에 넣기 전에 vector로 복사한다.
   게임 서비스 종료 및 저장 -> IOCP 스레드 종료 -> 객체 해제 순서로 종료한다.

실행 스레드 및 계층의 경계
- IOCP/Session은 네트워크 어댑터로서 TCP 수신과 프레임 조립을 계속 담당한다.
- ReceiveStep은 그 뒤의 게임 요청 큐를 소유한다. 계층 하나를 스레드 하나와 동일시하지 않는다.
- Service는 게임 작업 스레드와 연결 생존 여부/계정 로딩을 관리한다.
- 게임 스레드: 원시 패킷 기본 검사·파싱 -> 최초 연결인 경우 계정 로딩 및 플레이어 연결 -> 요청/인게임 검증 -> 처리 -> 전송 어댑터 호출.
- 최초 계정 로딩 전에 검사하도록 Service가 Runtime.DecodeInput을 호출한다. 이후 Dispatch에서는 이미 파싱한 요청을 다시 파싱하지 않는다.
- 검증과 실행은 동일 게임 스레드에서 연속 실행한다. 요청 사이에 다른 스레드의 게임 상태 변경은 없다.
- SendStep이 사용하는 GameplaySender 어댑터는 기존처럼 직렬화 후 Session.PostSend를 호출한다.
- 비동기 송신 완료 통지는 IOCP 작업 스레드가 처리한다.
- 기존 로그인/회원가입 처리는 PacketMethod 경로를 유지한다. 이번 게임 계층으로 이식한 것은 아니다.

책임 이동
- RequestDecoder.h/.cpp 삭제: Decode는 GameplayValidation에 통합.
- Core.h/.cpp 삭제: 기존 연결 및 조정 API는 ServerRuntime으로 옮김.
- Core의 요청 판정은 GameplayValidation, ACK 캐시/순번/보정/실행은 GameplayProcessor로 이동.
- 이동 가능 예산은 검증 시 수학적으로 계산만 하고, 실제 예산 갱신은 처리부에서 수행.
- GameplayProcessor는 Player.send를 직접 호출하지 않고 등록된 output 콜백으로 SendStep에 결과를 전달.
- IOCPServer는 Service, RequestDecoder, GameplayPersistence를 소유하거나 생성하지 않음.
- 공통 추상 Step 클래스는 추가하지 않음. 계층별 입력은 ServiceWork, ValidationResult, Event로 구분.

확인
- Visual Studio 프로젝트/필터에 새 클래스 등록, 삭제 클래스 참조 제거.
- 기존 게임 기능 회귀 테스트와 실제 서버 빌드 수행.
- 추가 테스트: 잘못된 크기 및 미인증 원시 패킷은 계정 로딩 전에 종료하고, 정상 원시 요청은 기존 게임 흐름으로 처리.
- 실제 TCP 테스트 통과: 로그인, 튜토리얼 검증, 이동 승인/보정, 재전송 중복 처리 방지, 중복 로그인 거절, 저장 및 송신 직렬화.
- 테스트 서버는 정상 종료했고 이번 테스트에서 생성한 임시 계정은 삭제함.
