3D 액션 MMORPG | Codex 구현 요청서
Unity C# 클라이언트 · 자체 C++ IOCP 서버

[1] 구현 목표와 기존 코드 활용
마비노기 모바일을 레퍼런스로, 같은 필드에서 플레이어들이 전투·채집·제작을 수행하는 3D 액션 MMORPG를 구현해줘. 내 캐릭터의 입력, 서버의 행동 판정, 각 클라이언트의 화면 표현까지 하나의 흐름으로 연결해줘.

먼저 저장소에서 공격 키 입력부터 패킷 송수신, 상태 전환, 애니메이션 재생까지 실제 호출 경로를 확인해줘. 기존 설계에서 언급된 InputManager, PlayerStateContexter, CombatManager, NetworkClient, PacketMethod, WorldLoader, Session, MapLayerize가 있다면 해당 책임을 활용해줘. 아래의 새 클래스명과 패킷 필드명은 역할을 설명하는 예시다. 수신 컴포넌트 이름은 요청한 표기인 ServerReciever를 사용한다.

[2] 서버와 클라이언트의 책임
• 클라이언트는 이동 방향, 공격 스킬·대상, 채집 대상, 제작 레시피 등 행동 의도를 전송한다.
• 서버는 로그인 세션에서 행동 주체를 식별한다. 위치·행동 상태·쿨타임·명중·HP·자원·보상은 서버가 확정한다.
• ACK는 요청자에게 요청 ID와 승인 여부·거절 사유를 돌려준다. 승인 ACK는 공격 명중이나 채집 완료를 뜻하지 않는다.
• 행동·상태 이벤트는 요청자와 같은 맵 내 관측 범위의 클라이언트에 전달한다. 내 캐릭터도 같은 이벤트로 행동을 표현한다. 개인 인벤토리 결과는 소유자에게 전달한다.

[3] 서버 요청 검증과 실행
Session이 TCP 스트림에서 완성된 패킷을 복원하고 길이·형식·종류를 검사한다. RequestDispatcher는 행동 요청을 캐릭터가 속한 맵 실행 큐로 전달한다. 같은 맵 상태에 대한 검증과 변경은 일관된 순서로 실행한다.

책임 연쇄의 ‘프로세스화’는 같은 서버 프로세스 안에서 재사용 가능한 검증 단계를 조합한다는 뜻이다. 각 IRequestValidator는 한 조건을 검사해 통과 또는 실패 사유를 반환한다. RequestPipeline은 요청 종류에 등록된 검사만 순서대로 실행한다. 첫 실패에서 거절 ACK를 보내고, 전부 통과하면 해당 핸들러가 상태를 갱신한다.

  공통 진입 검사   세션·캐릭터 연결, 맵 소속, 중복 요청, 생존·행동 제한
  이동            방향·허용 속도, 지형·원형 경계·벽 충돌 → 최종 위치 계산
  공격            스킬·자원·쿨타임, 대상 또는 조준 조건 → 공격 시작 및 타격 예약
  채집            대상·거리·도구·잔량·점유 가능 여부 → 자원 예약 및 채집 시작
  제작            레시피·재료, 필요한 경우 작업대·거리 → 재료 예약 및 제작 시작
  행동 취소       진행 중인 행동 ID와 취소 허용 여부 → 중단 및 예약 해제

같은 세션의 같은 요청 ID가 재전송되면 기존 처리 결과를 돌려준다. 쿨타임·재료·보상이 중복 반영되지 않아야 한다. 중복 판별은 재전송 시점에 달라질 수 있는 행동 상태 검사보다 먼저 처리한다.

[4] Unity 수신기와 오브젝트 구성
NetworkClient가 패킷을 역직렬화하고 메인 스레드 큐로 넘긴다. ServerReceiverManager는 EntityId로 ServerReciever를 조회한다. 수신기는 해당 메시지를 처리하는 컴포넌트에 전달한다. 관리자가 몬스터·플레이어·벽 종류별로 분기할 필요가 없도록 IServerMessageHandler<T> 같은 공통 계약을 둔다.

  내 플레이어       ServerReciever + 행동 표현 + 이동 표현 + 로컬 입력
  다른 플레이어     ServerReciever + 행동 표현 + 이동 표현
  몬스터            ServerReciever + 행동 표현 + 이동 표현
  건축물·자연물     ServerReciever + 문 개폐·파괴·고갈 등 필요한 상태 표현
  원형 경계·벽      ServerReciever + 경계 활성 여부·형상·크기 표현

WorldLoader가 스폰 패킷을 받아 객체를 생성하고 서버 ID를 연결한 뒤 수신기를 등록한다. 디스폰·맵 이탈 시 해제한다. 미리 배치한 건축물·자연물·경계는 서버 맵과 Unity 씬이 공유하는 배치 ID를 이용한다. 맵 진입 시 현재 상태를 받아 이미 열린 문이나 고갈된 자원도 올바르게 표시한다. 이동 경계는 서버에도 중심·반경·허용 방향 또는 벽의 충돌 형상을 보유한다.

[5] 플레이어 행동 상태와 생활 행동
Idle, Move, Attack, Looting을 기본 상태로 둔다. 내 입력 컨트롤러는 요청을 전송하고, 상태 컨텍스트는 서버가 확정한 전환을 적용한다. 몬스터 AI가 시작한 공격과 다른 유저가 시작한 공격도 Unity에서는 같은 행동 표현 경로를 사용한다.

서버 ActionController는 현재 상태, 행동 인스턴스 ID, 시작·종료 틱, 제한할 행동을 관리한다. 피격 시 단순 피격 연출과 행동 중단 여부를 스킬 규칙에 따라 구분한다. 사망은 진행 중인 행동을 중단시키고 새 행동 요청을 제한한다.

Looting은 일정 시간 행동을 제한하고 완료 시 결과물을 얻는 행동이다. 채집과 제작이 진행 시간·입력 제한·진행 바·취소·완료 처리를 공유한다. 채집은 대상과 자원 잔량, 제작은 레시피와 재료를 각 처리기에서 관리한다. 서버가 시작을 승인하면 내 화면은 진행 바를, 주변 화면은 작업 모션을 표시한다. 이동·공격 제한은 클라이언트 입력과 서버 검증 모두에 적용한다. 완료 시 현재 행동 ID를 확인하고 소비와 지급을 한 번만 반영한다. 중단 시 예약을 해제하고 ActionCancelled를 전송한다.

[6] 공격 키 입력 시퀀스 | 단일 대상 베기
requestId는 입력 요청과 ACK를 연결한다. actionInstanceId는 서버가 승인한 공격 한 번을 시작·타격·종료까지 추적한다. skillId는 사용할 기술의 종류다.

아래는 Mermaid 시퀀스 다이어그램 원문이다.

```mermaid
sequenceDiagram
    actor P as 플레이어
    participant C as 내 Unity 클라이언트
    participant V as IOCP 세션 및 맵 검증 체인
    participant A as 서버 ActionController
    participant O as 주변 Unity 클라이언트
    P->>C: 공격 키 입력
    C->>V: AttackRequest(requestId, skillId, targetId)
    V->>V: 세션에서 공격자 식별 후 맵 큐에서 검증
    alt 요청 거절
        V-->>C: AttackAck(requestId, 거절, 사유)
        C->>C: 요청 대기 해제 및 사유 표시
    else 요청 승인
        V->>A: 공격 실행
        A->>A: 상태 전환 및 자원 소모, 타격 틱 등록
        A-->>C: AttackAck(requestId, 승인)
        A-->>C: ActionStarted(공격자 ID, 행동 인스턴스 ID, 스킬 ID, 시작 틱)
        A-->>O: 동일한 ActionStarted
        Note over C,O: 공격자의 수신기로 모션 재생, 애니메이션 큐로 검 궤적 생성
        A->>A: 타격 틱에 행동 유효성 및 대상 충돌 검사
        alt 명중
            A->>A: 피해 계산 및 몬스터 HP 갱신
            A-->>C: HitResult(행동 인스턴스 ID, 대상 ID, 피해량, 남은 HP)
            A-->>O: 동일한 HitResult
            Note over C,O: 대상의 수신기로 HP 갱신 및 피격 표현
        else 빗나감
            A->>A: 피해 없이 공격 후속 시간 진행
        end
        A->>A: 공격 종료 및 다음 행동 상태 확정
        A-->>C: ActionEnded(행동 인스턴스 ID, 다음 상태)
        A-->>O: 동일한 ActionEnded
    end
```

[7] 애니메이션과 에셋 교체
ActionDefinition에 행동 길이, 타격 시점, 행동 제한 등 게임 규칙을 둔다. ActionVisualProfile에서 행동 ID와 캐릭터별 클립·재생 속도·이펙트 프리팹·부착 위치를 연결한다.
애니메이션 함수는 공격 모션의 타이밍 표시와 이펙트 생성 시점만 다룬다. 예를 들어 타격 시점이 0.35초인 베기는 서버가 시작 후 0.35초에 판정하고, 클라이언트는 그때 칼날이 타격 자세에 오도록 재생한다. 0.35초는 예시이며 스킬 데이터로 조정한다.
검 궤적은 모션 큐로 생성하고, 피격 효과·피해 숫자는 서버의 HitResult로 표시한다. 애니메이션 이벤트에서 대미지 계산, HP 변경, 상태 전환, 보상 지급을 실행하지 않는다. 이벤트가 없는 클립도 프로필의 큐 시각으로 같은 연출 함수를 호출할 수 있게 한다. 하나의 큐가 두 경로에서 중복 실행되지 않게 한다.

[8] 구현 완료 확인
• 클라이언트 2개에서 공격 한 번을 관찰한다. 내 캐릭터와 다른 클라이언트의 원격 캐릭터가 각각 모션을 한 번 재생하고, 명중한 몬스터의 HP가 양쪽에서 일치한다.
• 채집 중이거나 공격 쿨타임인 경우 거절 ACK가 오고 공격·자원 소모가 발생하지 않는다.
• 공격 시작 후 타격 시점 전에 대상이 범위를 벗어나면 궤적은 보이고 HP는 유지된다.
• 같은 요청을 다시 보내도 공격이 두 번 시작되거나 채집·제작 결과가 두 번 지급되지 않는다. 두 플레이어가 점유형 채집물 하나를 동시에 선택하면 한 명만 점유한다.
• 채집·제작의 완료와 중단을 각각 확인한다. 중단된 행동의 이전 타이머가 나중에 보상을 지급하지 않아야 한다.
• 이동 입력으로 원형 경계와 벽을 통과할 수 없으며 맵 재입장 시 정적 오브젝트의 최신 상태를 받는다.
• 공격 클립과 이펙트를 교체해도 같은 서버 규칙으로 타격이 처리된다.

작업이 끝나면 변경한 파일, 실제 입력부터 결과 반영까지의 호출 경로, 실행한 검증과 결과를 알려줘. 실행 환경 때문에 확인하지 못한 항목은 따로 표시해줘.
