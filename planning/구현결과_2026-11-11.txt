적용 기준
MMORPG_Codex_구현요청서.txt 원문과 구현기준_최신합의.txt를 적용했다.
플레이어는 후보 위치를 계산·예측하고 서버가 모든 이동 구간을 검증한다.
몬스터 이동·행동·HP, 공격 판정·시점, 채집·제작 결과는 서버가 결정한다.
최신 지시에 따라 기능마다 승인을 기다리지 않고 합의한 범위까지 진행했다.
MCP 연결은 확인됐으나 해당 세션에 편집/컴파일 기능이 노출되지 않아 승인된 Unity CLI로 같은 에디터를 제어했다.

실행 시작점
Assets/EverWindGameplay/Generated/GameplayVerification.unity
기존 씬과 기존 캐릭터/아이템/레시피 원본은 변경하지 않았다.
새 런타임은 EverWind.Gameplay 네임스페이스로 기존 클래스와 분리했다.
서버의 기존 로그인·Session·PacketMethod 경로를 유지하고 0x500 요청 분기를 추가했다.
기존 퀘스트·튜토리얼·장비 UI 등에 새 구조를 강제로 연결하지 않았다.

주요 코드
Assets/EverWindGameplay/Runtime/PlayerActions.cs
  NonCombatState / CombatState / LootingState / DeadState: Action 허용과 이동 표현 정책.
  MoveAction: 속도·방향과 MovementMotor의 공통 이동 실행.
  ApproachTargetAction : MoveAction: 대상/거리 유지, 정상 도착·대상 소멸·막힘·시간 초과 구분.
  KnockbackAction : MoveAction: 서버 넉백을 로컬 예측 표현. 직접 입력보다 우선한다.
  AttackAction: 대상/사거리 검사 후 요청. 이동 Action을 참조하지 않는다.
  ObtainAction / CraftAction: 채집·제작 요청과 서버 행동 ID 연결.
  HitAction: 캐릭터별 재사용하는 피격 표현. 일반 피격은 이동 제어권을 빼앗지 않는다.

Assets/EverWindGameplay/Runtime/PlayerActionController.cs
  입력, 접근과 후속 행동의 연결, 대상 고정, 교체·취소·인터럽트를 관리한다.
  선택한 대상 변경과 이미 실행 중인 공격의 대상을 분리한다.
  실행 세대와 서버 요청/행동 ID로 늦은 콜백을 걸러낸다.
  취소된 요청의 ActionStarted가 늦게 오면 해당 ID만 취소한다.
  행동 요청 시간초과 시 서버 실행 여부를 추정하지 않고 연결을 정리한다.

Assets/EverWindGameplay/Runtime/MovementMotor.cs
  Rigidbody 없이 BoxCast로 고정 장애물을 검사하고 원형 경계를 제한한다.
  이동 요청은 약 20Hz, 예측 위치 이력은 최대 128개다.
  서버 보정 세대가 바뀌면 오래된 예측을 폐기하고 서버 확정 위치로 보정한다.
  승인된 정상 응답은 이후 예측 위치를 매번 과거 위치로 되돌리지 않는다.

Assets/EverWindGameplay/Runtime/NetworkClient.cs
Assets/EverWindGameplay/Runtime/ServerTransceiver.cs
Assets/EverWindGameplay/Runtime/ServerTransceiverManager.cs
  하나의 TCP 연결 → 프레임 복원/역직렬화 → 메인 스레드 큐 → EntityId 등록부
  → 오브젝트 ServerTransceiver → IServerMessageHandler 경로로 수신한다.
  송신은 로컬 플레이어 Action → ServerTransceiver → 공통 NetworkClient다.
  원격 플레이어/몬스터에는 로컬 입력과 플레이어 이동 송신 권한을 붙이지 않는다.
  맵 변경 시 객체와 등록, 정적 경계, 인벤토리 표시를 초기화하고 스냅샷으로 복구한다.

EverWindServer/LoginServer/Gameplay/Protocol.h 및 클라이언트 Protocol.cs
  공통 TCP 헤더 4바이트, 요청 본문 52바이트, 이벤트 본문 108바이트.
  패킷 ID: 요청 0x500 / 이벤트 0x501. 기존 로그인 형식을 재사용한다.
  요청 ID, 맵 세대(Epoch), 보정 세대(Revision), 이동 순번, 행동 인스턴스 ID를 구분한다.
  서버 시점은 단조 시간 기반 초 단위 값이다. 패킷 순번을 시각 대신 사용하지 않는다.
  ACK는 요청 처리 결과이며 타격·채집·제작 완료를 뜻하지 않는다.

EverWindServer/LoginServer/Gameplay/World.cpp / World.h
  Service 실행 큐 한 곳에서 검증과 월드 변경을 직렬화한다.
  공통 검증 그룹 + 이동/공격/채집/제작/취소/맵 변경/부활별 검증 그룹을 조합한다.
  중복 요청을 먼저 확인하고 최근 512개 결과를 보관한다. 같은 ID의 다른 내용은 거절한다.
  검사 단계와 실행·전송·보상 처리를 분리한다.
  모든 이동 구간에 유효 수치·속도 예산·장애물·원형 경계를 검사한다.
  공격은 시작과 실제 타격 시점에 각각 필요한 조건을 검사한다.
  채집 점유, 취소 해제, 완료 1회 지급, 제작 재료 소비를 서버에서 처리한다.
  몬스터 배회/추적/공격/넉백은 서버에서 계산한다.
  unique_ptr로 모듈/검증기를 소유하고 shared_ptr로 플레이어 수명을 관리한다.
  Session 송신 콜백은 weak_ptr로 잡아 순환 소유를 피한다.
  기존 Session 송신 완료 처리도 부분 전송 잔여 바이트를 먼저 보내도록 보강했다.

  중복 모션 방지, HP/피격, 자원 고갈 표현을 담당한다.
GameplayHud / GameplayVisualCue: 진행 바, 상태/대상/인벤토리, 피해 숫자, 기본 검 궤적.

시각용 복사본 5개를 만들었다. 기존 에셋의 내장 AI/피해/이동 함수를 호출하지 않는다.
복사한 클립 27개에서 AnimationEvent를 제거했다. 런타임에서도 fireEvents와 Root Motion을 끈다.

실제 호출 흐름
공격: 1/2 입력 → Controller가 대상/목적 저장 → 필요하면 전투 모드 요청
 → ApproachTargetAction → ReachedTarget일 때만 AttackAction
 → ServerTransceiver.Send → NetworkClient → 기존 IOCP Session
 → Gameplay Service 큐 → 중복/공통/공격 검증 → 서버 행동 시작
 → ActionStarted → 같은 송수신기/표현 경로로 자신과 원격 클라이언트 모션
 → 서버 타격 시점 재검사 → Hit 이벤트 → HP/피격/피해 숫자 → ActionEnded.
채집/제작: 요청 → 검증 → 점유/작업 시작 → 진행 바·작업 모션
 → 취소 시 점유 해제, 완료 시 소비/보상 1회 → 개인 인벤토리 이벤트.
직접 이동: 입력 → MoveAction → Motor의 BoxCast/예측 → 이동 요청
 → 서버 전 구간 검증 → 승인 또는 Revision 증가와 확정 위치 보정.

검수 시 유의할 현재 범위
- 별도 씬의 평면 XZ 검증 맵이다. 기존 고도 지형/경사면/실제 던전 배치를 자동 변환하지 않았다.
- 접근은 직선 이동이다. 장애물에 막히면 Blocked로 종료한다. NavMesh/BT는 도입하지 않았다.
- 작은 맵 전체를 관측 범위로 사용한다. 거리별 AOI 필터·대규모 부하 검증은 하지 않았다.
- 새 코어의 인벤토리/자원/HP는 서버 실행 중 메모리 상태다. 재로그인/서버 재시작용 DB 영속화,
  기존 인벤토리 UI와의 통합은 연결하지 않았다. 기존 저장 데이터를 검증 맵 좌표로 덮어쓰지 않는다.
- 현재 스킬에는 별도 MP/스태미나 비용이 없고 기존 레시피에는 도구/작업대 요구 데이터가 없다.
  정의되지 않은 도구·작업대·소모 자원 규칙을 임의로 만들지 않았다.
- 실제 계정 두 개로 운영 IOCP 로그인부터 전투까지의 통합 검증과 외부 인터넷/포트포워딩은 미확인이다.
- 기존 씬을 이 구조로 전환하거나 기존 서버 MapData/레거시 전투 경로를 제거하지 않았다.
