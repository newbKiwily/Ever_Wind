서버 초기화 및 소유·참조 관계 — 2026-11-12

1. 서버 구동
main.cpp는 ServerApplication.Initialize -> Start -> 명령 대기 -> Shutdown만 호출한다.
생성자는 구성요소의 참조 및 기본값만 준비한다. 소켓·DB 연결, 규칙/맵 파일 로딩, 게임 스레드 실행은 명시적인 단계로 옮겼다.

ServerApplication.Initialize의 순서:
  InitializeIOCP
    Winsock, 소켓, bind, Completion Port 준비. listen 및 작업 스레드는 아직 시작하지 않는다.
  InitializeDatabase
    DB 연결, Queries, GameplayPersistence 생성.
  InitializeGame
    GameRules 로딩, ServerRuntime의 파이프라인 연결, DB 아이템 ID 매핑 설정.
  InitializeMaps
    DB MapInfo/Monster 설정 조회, 지형·높이·맵 경계 및 스폰 영역 구성.
  InitializeWorldObjects
    몬스터, 채집물, 충돌 영역, 트리거 배치.
  ConnectCallbacks
    인증 입력, 게임 입력, 저장·조회 및 전송 콜백 연결.

모든 초기화가 성공한 뒤 Start에서 게임 작업 스레드 -> IOCP listen/작업 스레드/접속 수락을 시작한다.
StartupPhase와 GamePhase로 초기화 순서를 표현하며, 게임 시스템 준비 전 Start와 중복 Start/중지 후 재시작은 거부한다.
초기화가 실패하면 이후 단계를 진행하지 않고 준비한 자원을 해제한다.

2. 최상위 소유 관계
ServerApplication
  DatabaseComponents db
    unique_ptr<DBManager> connection
    unique_ptr<Queries> queries
    shared_ptr<GameplayPersistence> persistence
  NetworkComponents network
    unique_ptr<SessionManager> sessions
    unique_ptr<IOCPServer> server
  IngameComponents ingame
    unique_ptr<Service> service
    unique_ptr<PacketMethod> authentication

폴더:
  DB/ = DB 연결·SQL·저장 변환
  Network/ = IOCP·세션·IOContext·전송 어댑터
  Gameplay/ = 인게임
    Authentication/PacketMethod = 로그인·회원가입 어댑터
    Rule/GameRules = 스킬·아이템·제작·퀘스트·정책 및 맵/오브젝트 설정 행
    Map/WorldState = 실행 중인 플레이어/맵, 지형 및 맵별 오브젝트 상태
    Refill/RefillSystem = 채집물 리필 검증·적용 및 몬스터 재생성
    Validation/ = 기존 책임 연쇄 검증기
  Util/ = SHA256 및 보존한 기존 타이머 유틸리티

3. 인게임 소유 및 참조
Service가 ServerRuntime을 소유하고 게임 작업 스레드를 관리한다.
ServerRuntime이 GameRules, WorldState, RefillSystem, ServerSteps를 소유한다.
WorldState는 const GameRules&를 참조하고 플레이어·맵 상태를 소유한다.
Map 구조체가 해당 맵의 몬스터·채집물·설치물·충돌 영역·트리거·높이 데이터를 소유한다.
RefillSystem은 WorldState&를 참조한다. 채집물/몬스터의 별도 복사본을 소유하지 않는다.
GameplayValidation과 GameplayProcessor는 동일한 RefillSystem을 참조한다.
검증부가 규칙을 판정하고 처리부가 상태를 변경하는 원칙과 기존 next 책임 연쇄를 유지한다.
기준 데이터 참조는 world.rules.items/skills/recipes/quests 등으로 명시한다.

4. 외부 경계
IOCPServer는 DB·PacketMethod·Service 클래스를 참조하지 않는다.
인증 입력 및 게임 입력은 ServerApplication에서 연결한 콜백으로 전달한다.
SessionManager는 세션만 관리하고 더 이상 맵을 소유하지 않는다.
인증 어댑터는 Queries&와 SessionManager&, 맵 존재 여부를 조회하는 콜백을 받는다.
인게임은 세션/SQL 호출 대신 기존 전송·저장·조회 콜백을 사용한다.
GameplayPersistence는 Gameplay.rules를 다시 읽지 않고 GameRules에서 읽은 아이템 정의로 매핑을 초기화한다.
기존 DB 스키마 및 로그인/회원가입·게임 패킷의 바이트 형식은 유지한다.

5. 기존 중복 경로 정리
맵의 단일 실행 상태는 WorldState.maps이다.
SessionManager의 MapDataManager 소유 및 초기 등록 경로를 제거했다.
로그인 중 기존 맵의 플레이어/몬스터를 별도로 전송하던 경로를 제거했다.
플레이어/몬스터 스냅샷과 월드 입장은 기존 권위형 Join 처리에서 제공한다.
이미 수신 차단되어 있던 구형 인게임 패킷 처리 함수와, 그것만 사용하던 MapData/MapDataManager/Enemy 클래스를 제거했다.
PacketMethod는 기존 로그인/회원가입 처리와 해당 응답만 유지하여 Authentication으로 이동했다.
기존 Timer/TimerManager/TimerCompare는 Util로 이동하여 보존했다. 새 리필 처리와 연결하거나 별도 타이머 스레드를 시작하지 않는다.

6. 종료
접속 수락 중지 -> 게임 스레드 중지 및 저장 -> 세션 종료/IO 완료 정리 -> IOCP 스레드 종료 -> 게임 객체 해제 -> 네트워크 객체 해제 -> DB 객체 해제.
완료 처리 중 다음 IO를 발행하는 구간까지 추적하여, 종료 시 IOContext와 그 안의 Session 참조가 남지 않도록 한다.
